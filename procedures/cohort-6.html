COHORT 6 · 🚀 Forward Deployed Engineering Mindset

🧭 Can explain what a Forward Deployed Engineer does

🎯 Objective
Be able to define "Forward Deployed Engineer" (FDE) in your own words.
✅ Key Results
  • Can state the FDE definition from the session in one sentence
  • Can name one required FDE skill besides coding (e.g. stakeholder communication)
📋 Prerequisites
  • None
🪜 Steps
  1. Re-read the FDE definition in Cohort 6
  2. Write your own one-sentence definition
  3. List 2-3 non-technical skills the role also requires

COHORT 6 · 🚀 Forward Deployed Engineering Mindset

📅 Understand the "Day 1 deployment" philosophy (ship before you polish)

🎯 Objective
Understand why shipping something live on day one beats a polished late release.
✅ Key Results
  • Can explain one benefit of deploying immediately vs. waiting
  • Applied this philosophy to your own project this session (see Environment & Deployment)
📋 Prerequisites
  • None
🪜 Steps
  1. Re-read the Day-1 deployment reasoning in Cohort 6
  2. Compare it to the traditional "build fully, then ship" pipeline
  3. Note one risk this philosophy avoids (e.g. late, costly surprises)

  • Cohort 6 session notes
COHORT 6 · 🚀 Forward Deployed Engineering Mindset

🗣️ Practiced explaining a technical decision to a non-technical stakeholder

🎯 Objective
Practice translating a technical choice into plain language for a non-technical audience.
✅ Key Results
  • One technical decision explained in plain language, out loud or in writing
  • Feedback obtained from a peer or self-reviewed for jargon
📋 Prerequisites
  • A project or technical decision to explain (see your own repo, below)
🪜 Steps
  1. Pick one technical decision from your project (e.g. "why GitHub Pages")
  2. Explain it in 2-3 sentences with no jargon
  3. Ask a peer (or re-read it yourself) to check it's actually clear

COHORT 6 · 🐙 GitHub Project Workflow

📂 Created a public GitHub repository with a descriptive name

🎯 Objective
Create a properly named public repository for your own project.
✅ Key Results
  • Repository created and set to Public
  • Name uses lowercase-with-hyphens and describes the project, not a generic label
📋 Prerequisites
  • A GitHub account
🪜 Steps
  1. Go to GitHub → New Repository
  2. Choose a descriptive, hyphenated name (avoid "solution-v1")
  3. Set visibility to Public and create it
🔗 References
  • GitHub: Create a repo
  • Cohort 6 session notes

COHORT 6 · 🐙 GitHub Project Workflow

💻 Cloned the repo locally and navigated it via terminal (cd, mkdir, git clone)

🎯 Objective
Get comfortable with the basic terminal commands needed to work with a repo locally.
✅ Key Results
  • Repository cloned to a local `projects` folder
  • Comfortable using `cd`, `mkdir`, and `git clone` without help
📋 Prerequisites
  • Git installed
  • Repository created (see above)
🪜 Steps
  1. Open a terminal and run `mkdir projects` then `cd projects`
  2. Run `git clone `
  3. Run `cd` into the cloned folder and list its files

COHORT 6 · 🛠️ Environment & Deployment

⚙️ Installed your dev tools (Homebrew/App Store on Mac, or winget/PowerShell on Windows)

🎯 Objective
Have a working package manager set up for installing dev tools going forward.
✅ Key Results
  • Homebrew (Mac) or winget (Windows) confirmed working
  • One tool successfully installed through it
📋 Prerequisites

🪜 Steps

  2. Windows: open PowerShell as Administrator and confirm `winget` works
  3. Install one tool (e.g. Git) through your package manager to confirm it works
🔗 References
  • Homebrew
  • Winget docs
  • Cohort 6 session notes

COHORT 6 · 🛠️ Environment & Deployment

🌐 Deployed a project live via GitHub Pages + GitHub Actions

🎯 Objective
Get your own project live on the internet using GitHub Pages and Actions.
✅ Key Results
  • GitHub Pages enabled for your repo
  • A GitHub Actions workflow run completed successfully
  • Live URL opens and shows your project
📋 Prerequisites
  • Repository created and cloned locally (see GitHub Project Workflow)
🪜 Steps
  1. Add an `index.html` (or static site) to your repo
  2. Go to Settings → Pages and set the source to GitHub Actions (or a branch)
  3. Push a commit and watch the Actions tab for a successful run
  4. Open the resulting github.io URL
🔗 References
  • GitHub Pages docs
  • GitHub Actions docs
  • Cohort 6 session notes
